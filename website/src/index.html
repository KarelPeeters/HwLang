A modern hardware description language that compiles to plain Verilog

KHDL checks integer ranges, clock domains and register resets every time you compile. Interfaces and generics replace copied port lists and code generators. The output is plain Verilog 2005, so it works with the simulation, synthesis and lint tools you already use.

What KHDL does differently

        
Each of these is checked or generated by the compiler, on every build.

    


    

        

            
Integers know their range

            

                Integer types are ranges: uint(8) holds 0 to 255, int(-8..=7) holds −8 to 7.
                Arithmetic results get the range they actually need, and every assignment is checked.
                count + 1 has type int(1..257), so storing it in a uint(8) is a
                compile error instead of a silent wrap-around.
            

            

                The compiler also follows your control flow. In the else branch below,
                count can't be 255, so count + 1 fits. If you want wrap-around, write it:
                (count + 1) % 256.

                The same arithmetic in Verilog
                

                    In Verilog, the width and signedness of an expression come from its context. With
                    a = 7 and b = -2, this adder outputs −11: one operand is unsigned, so
                    b is zero-extended to 01110 (14), and the 5-bit sum 10101 is
                    read back as a signed number. That's what the standard prescribes, so tools accept it.
                    (Example from Jan Decaluwe.)
                

                

                    
module MixedAdd(
    input wire [2:0] a,
    input wire signed [3:0] b,
    output wire signed [4:0] result
);
    assign result = a + b;  // 7 + -2 = -11
endmodule

                    

                

                
In KHDL the ranges are the types, and 7 + -2 is 5.

            

        

    


    

        

            
Clock domains are part of the type

            

                Every port and signal has a domain: sync(clk) for signals that belong to a clock,
                async for those that don't. The compiler checks every assignment and connection, so an
                accidental clock-domain crossing is a compile error, not something a separate CDC tool reports
                weeks later.
            

            

                Crossing on purpose is explicit, with unsafe_value_with_domain, so every crossing is easy
                to find in review.

Code runs top to bottom, registers are declared

            

                There is one assignment operator, and every statement sees the result of the statements before it,
                like in software. Registers are declared with reg, registered outputs with
                reg wire, and each needs a reset value or an explicit undef. The compiler
                generates Verilog that simulates and synthesizes the same way.
            

            

                That makes logic with several dependent steps easy to write. This module adds 5 to a stream of values,
                with ready/valid handshakes on both sides and a skid register, so it can still take a value every
                cycle. Each step only has to make sense given the steps before it, so you can check it like software
                instead of reasoning through every combination of states and inputs.

                The same module in VHDL
                

                    VHDL variables also update immediately, so the steps can be written the same way. But variables
                    only exist inside a process, and the ports have to be driven by signals. So every register is
                    declared twice, copied into a variable at the start of the process, and copied back at the end.
                

                
architecture rtl of add_five is
    signal r_skid_data    : unsigned(7 downto 0);
    signal r_skid_valid   : std_logic;
    signal r_output_data  : unsigned(7 downto 0);
    signal r_output_valid : std_logic;
begin

    input_ready <= not r_skid_valid;
    output_data <= r_output_data;
    output_valid <= r_output_valid;

    process(clk)
        variable v_skid_data    : unsigned(7 downto 0);
        variable v_skid_valid   : std_logic;
        variable v_output_data  : unsigned(7 downto 0);
        variable v_output_valid : std_logic;
    begin
        if rising_edge(clk) then
            if rst = '1' then
                r_skid_valid <= '0';
                r_output_valid <= '0';
            else
                -- copy registers into variables
                v_skid_data := r_skid_data;
                v_skid_valid := r_skid_valid;
                v_output_data := r_output_data;
                v_output_valid := r_output_valid;

                -- input handshake
                if input_valid = '1' and v_skid_valid = '0' then
                    v_skid_data := input_data;
                    v_skid_valid := '1';
                end if;

                -- output handshake
                if output_ready = '1' then
                    v_output_valid := '0';
                end if;

                -- processing
                if v_skid_valid = '1' and v_output_valid = '0' then
                    v_output_data := v_skid_data + 5;
                    v_output_valid := '1';
                    v_skid_valid := '0';
                end if;

                -- copy variables back into registers
                r_skid_data <= v_skid_data;
                r_skid_valid <= v_skid_valid;
                r_output_data <= v_output_data;
                r_output_valid <= v_output_valid;
            end if;
        end if;
    end process;

end rtl;

            

            

                Blocking and nonblocking assignments in Verilog
                

                    Verilog has blocking (=) and nonblocking (<=) assignments. Use the
                    wrong one, and the result can depend on which always block the simulator happens to
                    run first. In this two-stage pipeline, the first block uses = where both assignments
                    should have been <=, and two open-source simulators we tried disagree on its
                    output.
                

                
module RacyPipeline(input wire clk, rst, data, output reg result);
    reg stage;
    always @(posedge clk) begin
        if (rst) stage = 0;  // should have been <=
        else stage = data;   // should have been <=
    end
    always @(posedge clk) begin
        if (rst) result <= 0;
        else result <= stage;
    end
endmodule

            

        

    


    

        

            
Interfaces instead of port lists

            

                An interface groups the signals of a bus, and a view gives the direction of each signal
                for one side. A module takes the whole bus as one port, directions flip between producer and consumer,
                and connecting two modules takes one line.
            

            

                Interfaces can be generic too: Stream(T) carries any payload type, from a byte to a
                struct.

Generics are ordinary code

            

                Parameters can be numbers, types, functions or modules, and elaboration is regular code. A
                for loop in the port list creates numbered ports, with names built from format strings.
                Types can depend on parameters too: total is exactly wide enough for the sum of
                inputs bytes.
            

            

                sum has no declared type: its range follows each assignment, so every adder in the chain
                is one bit wider than the last. In Verilog and VHDL, a port list is fixed, so a variable number of
                inputs needs an array port or a script that generates the source.

Plain Verilog output

                
A simple subset of Verilog 2005 that any EDA tool reads. Existing IP can be instantiated as
                    external modules.

            

            

                
Clear error messages

                
Diagnostics point at the problem and at the declaration that caused it, like the ones above.

            

            

                
Editor support

                
The compiler includes a language server, so editors show the same errors as you type. There's a
                    VS Code extension.

            

            

                
Python bindings

                
Elaborate modules, call functions and simulate with Verilator from Python, with values converted
                    automatically.

            

            

                
Formatter

                
The compiler comes with a formatter, so every project can use one consistent code style.

            

            

                
Fast

                
The compiler is multithreaded down to individual items and elaborated modules, so large projects
                    compile quickly.
